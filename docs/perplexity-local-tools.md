# Perplexity 本地工具桥接契约

本文说明 Perplexity Web 上游到本地 Claude Code 工具执行的桥接契约、限制与验收方法。

## 契约

- 本地工具仍走既有链路：客户端 `tools[]` → 注入 `LOCAL ACTION PROTOCOL` → 模型输出 JSON → 校验后转 `tool_use` → 客户端本机执行 → `tool_result` 续接同一线程。没有新增执行系统，也不接入任何账号云端连接器。
- 新线程首轮：工具协议始终放在**最后一个**提交分片（唯一会被回答的分片）。协议加正文超过 `perplexityDefaultMaxPromptRunes`（38k）时只拆会话正文，且**只有最后一片**为协议让出空间（`max - 协议 - 2 - 分片头预留 200`），前面的 ACK 分片仍按常规预算填满，不丢正文、保持顺序（例如 34k 协议加 120k 正文约 5 片，而不是几十片）。没有任意的 4000 rune 门槛：仅当协议加最终提醒（`perplexityLocalMiddlewareReminder`）在一个上游提示里放不下时，才返回 `ErrToolBridgeNoTool` 分类的显式错误，不会静默丢 schema。
- 续接轮（同线程）：只发增量与提醒，工具协议沿用首轮线程里的那一份。
- 拒绝纠正：仅当有真实 `clientTools` 且存在协议时才识别；最多纠正一次。识别两类语义：
  1. 声明没有本地通道 / 无法在本机执行 / 只是快照；
  2. 以云端服务、代码沙箱、云端 GitHub 连接替代本地能力。
- 纠正重试：新开上游线程，**重放完整上下文**（系统注记、早期用户约束、`LOCAL TOOL RESULT` 工具结果、最新一轮），在最终提醒之前追加一段更正文案；同样走分片，协议只在最后一片。更正文案不写死任何具体工具名，只要求使用协议 `## Functions` 中实际声明的函数；描述能力时也只提已声明的函数。重试返回为空、传输失败或仍为拒绝时，返回中性可重试错误（复用 `ErrToolBridgeNoTool`，客户端侧文案不含上游品牌），并丢弃被污染的线程绑定。
- 不拦截：普通问候、无工具请求、身份问答、JSON/代码围栏/`<tool_call>` 开头的回复、用户自己引用了同一措辞的回复、超过 1500 rune 的长回答。

## 限制

- 识别是措辞与语义匹配，不是云端工具的安全沙箱。上游已经执行的服务端动作无法被事后拒绝撤回，是否存在服务端禁用工具的契约仍未验证。
- 纠正重试开启新上游线程，重放的是当前请求里带的完整消息历史；若历史超过 38k 会按分片规则拆分，客户端本身没再发送的更早内容无法找回。
- 同线程续接轮不重发协议；会话中途工具集合变化仍沿用既有的上下文更新逻辑。

## 验收

局部回归：

```bash
go test ./internal/proxy -run 'TestPerplexity|TestClientFacingErrors' -count=1
```

真实链路验收：

1. 启动本地桥接与 `python3 claude-pplx.py`（默认连接 `http://127.0.0.1:18082`），让模型读取一次性随机生成的非敏感文本文件，核对 `tool_use` → 本机执行 → `tool_result` → 正文里的随机值。
2. 单独发“你好”，应得到正常文本，不应被强制执行工具，也不应出现云端能力说辞。
